Eval Harness Pipeline

EvalController orchestrates a load → run → score pipeline with upfront validation to surface all config errors before the eval loop starts.

1

CaseLoader

Reads cases/{agent}/{cat}/TC-*.yaml, resolves stub fixture references, validates schema

→
2

Upfront Validation

Checks tool_responses match MAF YAML tools; equity cases have required demographic metadata

→
3

StubToolMiddleware

Injects scripted YAML responses; records full tool call trajectory; never calls real backend

→
4

MafAgent.run()

Executes MAF agent with stub middleware; returns raw response + trajectory

→
5

Judge / BaseScorer

3-stage pipeline: veto → pre-LLM → LLM rubric → JudgeResult (score, passed, rationale)

→
6

EvalResults

Aggregated results → JSON output or branded PDF report for compliance officers

BaseScorer — 3-Stage Pipeline

🚫

Stage 1 — Veto Check

Deterministic must_not_contain string matching. Any match returns 0.0 immediately, short-circuiting the LLM call.

🔍

Stage 2 — Pre-LLM Hook

Optional category-specific deterministic check (e.g., PHI regex in PrivacyGuard, disclaimer presence in triage). Returns 0.0 or passes through.

🧠

Stage 3 — LLM Rubric

Category-specific prompt built by _build_prompt() → Azure OpenAI judge → parsed JSON score 0.0–1.0 with rationale.

Category Scorers

Seven specialized scorers, each covering a distinct evaluation dimension. All inherit from BaseScorer and override _build_prompt().

FunctionalScorer

Trajectory-aware rubric: evaluates whether the agent achieved the expected booking, cancellation, or lookup outcome. Score 0.0–1.0.

SafetyEscalator

HIGH severity: emergency → 911/ER directive required. MEDIUM: out-of-scope refusal required. Default threshold: 0.9 (higher bar).

PrivacyGuard

PHI regex pre-LLM check catches common PII patterns (SSN, DOB, MRN). LLM rubric validates safe PHI handling. HIPAA-aligned.

EquityAnalyzer

Requires demographic metadata (patient_age, language, insurance). Scores equitable treatment across patient populations.

UrgencyTriageScorer

Validates urgency classification correctness (HIGH/MEDIUM/LOW) and mandatory clinical disclaimer presence in triage responses.

HITLRoutingScorer

Two-stage: structural signal validation (pre-LLM checks reason_code, confidence) → semantic LLM evaluation of routing appropriateness. 7 valid reason codes.

RegulatoryComplianceScorer

Evaluates HIPAA, consent, and regulatory compliance behaviors. Validates consent acknowledgment flow and data handling language.

HITL Reason Codes

Seven valid codes enforced by VALID_REASON_CODES frozenset in hitl_routing.py:

ambiguous_intent consent_declined eligibility_failure identity_verification_failure no_available_slots red_flag_symptom late_cancellation_policy

Demo UI — Feature Walkthrough

The Streamlit demo (streamlit run demo/app.py) provides a full interactive experience for clinicians and evaluators to explore agent behavior live.

🔒

HIPAA Consent Gate

Full-screen modal blocks all interaction until patient acknowledges the Notice of Privacy Practices. Decline ends the session with a clear error message.

📋

Scenario Picker

8 pre-built demo scenarios: routine booking, urgent triage, identity verification failure, Spanish scheduling, prior auth, waitlist, late cancellation, and Medicare.

💬

Live Patient Chat

Multi-turn conversation with the orchestrator agent. The disclaimer is auto-injected below triage responses when the "not a medical diagnosis" fragment is absent.

🔍

Agent Trace Panel

Per-turn collapsible trace showing sub-agent calls, tool invocations, fixture names, stub responses, and HITL signals per event.

⚠️

HITL Escalation Alert

Amber warning banner appears when the orchestrator returns a HITL signal, displaying the reason code and confidence level prominently.

✉️

SMS Reminder Badge

After confirmed bookings, a ✉️ "Reminder sent to patient via SMS" badge appears when send_appointment_reminder is detected in the turn trace.

📊

KPI Metrics Sidebar

Expandable panel in the sidebar compares baseline vs agentic metrics: scheduling time, no-show rate, HITL escalation rate, and patient satisfaction score.

🌐

Spanish Scenario

Full end-to-end Spanish scheduling path. Orchestrator language detection rule routes to Spanish-capable response flow. Validates equity in multilingual access.
